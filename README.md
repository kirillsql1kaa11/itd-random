# ИТД — Кто автор?

Викторина: угадай автора поста по скриншоту из соцсети ИТД. Next.js 16 (App Router) + Supabase (Postgres + Storage).

## Маршруты

| Путь | Назначение |
| --- | --- |
| `/` | Главная: никнейм, выбор режима, запуск игры |
| `/play` | Игра (без активной сессии перенаправляет на `/`) |
| `/result` | Итоги раунда и сохранение результата |
| `/leaderboard` | Рейтинг: фильтр по режиму и пагинация на сервере |
| `/authors` | Каталог авторов |
| `/stats` | Локальная статистика игрока |
| `/admin` | Панель управления и аналитика |

Игровое состояние живёт в общем клиентском контексте (`components/AppProvider.tsx`) и переживает переходы между маршрутами. Перезагрузка страницы сбрасывает незавершённую игру.

## Переменные окружения

Создайте `.env.local` (не коммитится):

```
SUPABASE_URL=https://<project>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<Secret key>
API_SECRET=<случайная строка не короче 32 символов>
ADMIN_PASSWORD=<необязательно: одноразовый пароль для первого входа>
```

`SUPABASE_SERVICE_ROLE_KEY` — это **Secret key** из Supabase Dashboard → Project Settings → API Keys. Publishable (anon) ключ не подходит: после включения RLS все операции идут только через серверную роль. Приложение не использует Supabase напрямую из браузера.

`API_SECRET` подписывает токены вопросов, игровые сессии и токены администратора. Смена значения инвалидирует все активные токены.

Для деплоя на Vercel добавьте те же переменные в Project → Settings → Environment Variables.

## Миграции Supabase

Выполните файлы по порядку в Supabase Dashboard → SQL Editor:

1. `supabase/migrations/202610170001_sessions.sql` — таблицы `game_sessions`, `game_answers`, новые колонки `leaderboard`.
2. `supabase/migrations/202610170002_functions.sql` — RPC `record_answer`, `submit_game`, представление `question_stats`.
3. `supabase/migrations/202610170003_rls.sql` — включает RLS на всех таблицах (политик для anon нет, доступ только через service role).
4. `supabase/migrations/202610170004_storage.sql` — публичный бакет `screenshots` для чтения.
5. `supabase/migrations/202610170005_lockdown.sql` — удаляет все старые политики с таблиц, отбирает права у anon/authenticated, чистит легаси-записи rate limit. Обязателен, если таблицы создавались под старую версию приложения: без него старый публичный ключ читает базу напрямую.

После пятой миграции старая (текущая на Vercel) версия приложения перестанет работать: она ходила в базу под anon-ключом. Поэтому порядок такой: сначала добавьте переменные в Vercel, затем примените пятую миграцию и сразу задеплойте новую версию (или примените миграцию буквально перед пушем).

Рекомендуемый порядок для продакшена:

1. Возьмите Secret key и пропишите его в Vercel и локально.
2. Примените миграции 1–4.
3. Задеплойте новую версию приложения.
4. Примените миграцию 5 (`lockdown`) и смените пароль администратора: старый пароль лежал в базе открытым текстом и до блокировки был доступен по публичному ключу.

Старая версия кода тоже читает `SUPABASE_SERVICE_ROLE_KEY`, поэтому между шагами 1 и 3 она продолжит работать.

## Первый вход в админку

Вариант А (скрипт):

```
node --env-file=.env.local scripts/set-admin-password.mjs "надёжный-пароль"
```

Вариант Б: задайте `ADMIN_PASSWORD` в окружении и войдите этим паролем — приложение само сохранит scrypt-хеш и удалит `ADMIN_PASSWORD` из реестра. После первого входа переменную можно убрать.

Пароли хранятся как scrypt-хеш в `admin_settings` (`admin_password_hash`). Легаси-запись `admin_password` с открытым паролем мигрируется автоматически при первом успешном входе.

## Перенос скриншотов в Storage

Если в базе остались скриншоты в формате base64 (`data:image/...`), перенесите их в бакет:

```
node --env-file=.env.local scripts/migrate-screenshots.mjs
```

Скрипт жмёт изображения в WebP (до 1200px) и обновляет записи в `posts` и `suggestions_posts`.

## Безопасность

- Секреты не хранятся в коде: всё читается из переменных окружения.
- Все таблицы закрыты RLS, доступ только у service role через серверные API.
- Токены вопросов привязаны к игровой сессии, очки считает сервер (`record_answer`), повторная отправка ответа и результата идемпотентна.
- Рейтинг сохраняется только один раз на сессию (`leaderboard.session_id` уникален).

### Ротация ключей

Раньше Supabase-ключ и `API_SECRET` лежали прямо в `lib/config.ts` и попали в публичный репозиторий. Их обязательно нужно сменить:

1. Supabase Dashboard → Project Settings → API Keys: отзовите старый publishable ключ и создайте новые publishable/secret ключи. Обновите `.env.local` и переменные Vercel.
2. Придумайте новый `API_SECRET` (32+ случайных символов) и обновите его локально и на Vercel.
3. Войдите в админку и смените пароль администратора, если он мог быть известен посторонним.

Историю git можно почистить отдельно (`git filter-repo` / BFG + пуш с перезаписью), но ротация ключей делает старые значения бесполезными и обязательна в любом случае.
